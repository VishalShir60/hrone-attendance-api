# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 35-37) | Divides seconds by 60 and truncates to int before comparing against grace period (`minutes > 10`). Also naively uses `replace()` without converting to IST. | Punching in at 09:40:01 on a 09:30 shift: elapsed seconds is 601 (10.016 min), which casts to 10. `10 > 10` is False, returning 0 late minutes instead of 10. | Converted both datetimes to IST, checked if elapsed seconds strictly exceed 600 (`elapsed_sec > 600`), and if so, calculated `elapsed_sec // 60`. |
| 2 | `compute_late_minutes` (line 35) | Doesn't handle overnight shifts (e.g. 22:00 to 06:00) where shift end lands on the following day. | Punching in at 02:00 on a night shift gets assigned today's date instead of yesterday's shift date, and late minutes calculations blow up. | Added `get_attendance_date` with R1 logic: if `shift_end <= shift_start` and punch-in is earlier than `shift_end`, anchor it to the previous calendar day. |
| 3 | `compute_work_hours` (line 41) | Uses Python's built-in `round()`, which applies banker's rounding (round half to even) instead of standard half-up. | A 2.125-hour shift (7,650 seconds) rounds down to 2.12 instead of up to 2.13 (violating R4). | Used Python's `decimal.Decimal` with `ROUND_HALF_UP` to round work hours to 2 decimal places. |
| 4 | `compute_overtime` (lines 44-47) | Counts any minutes past shift end as overtime, ignoring R3's 30-minute minimum threshold. Also subtracts naive and aware datetimes. | Punching out at 18:35 on an 18:30 shift gives 5 minutes overtime instead of 0. Subtracting naive UTC from aware IST throws `TypeError`. | Anchored shift end in IST (next day for overnight shifts), verified `elapsed_seconds >= 1800`, and returned `elapsed_seconds // 60` only if the threshold is met. |
| 5 | `EmployeeIn` (lines 53-61) | `EmployeeIn` lacks input validation: accepts invalid employee codes, identical shift start/end times, and malformed dates. | `POST /employees` with `shift_start: "09:00", shift_end: "09:00"` or `emp_code: "foo"` returned 201 instead of 422. | Added regex validation for `emp_code` (`^EMP\d{4,6}$`), date parsing on `joined_on`, and a validator ensuring `shift_start != shift_end`. |
| 6 | `PunchInIn` (lines 63-67) | `PunchInIn` has loose types: accepts floats, strings, 10-digit epoch seconds, or arbitrary status values. | Passing epoch seconds like `1720257000` or `status: "VACATION"` was accepted instead of failing with 422. | Added custom `EpochMillis` type validator checking the millisecond range (`100000000000` to `4102444800000`) and restricted `status` to `PRESENT`, `WFH`, `ON_DUTY`. |
| 7 | `health` (lines 72-74) | Always returns 200 OK without actually checking if MongoDB is reachable. | If MongoDB goes down or isn't running, `GET /health` still returns `{"status": "ok"}` with 200 instead of 503. | Ran a `ping` command against MongoDB in a try/except block, raising 503 if the database is unreachable. |
| 8 | `create_employee` (lines 79-80) | Classic check-then-insert race condition on `emp_code`: runs `find_one` before `insert_one`. | Sending two simultaneous `POST /employees` with the same `emp_code` creates duplicate employee documents. | Created a unique index on `employees.emp_code` at startup and caught `DuplicateKeyError` to return 409. |
| 9 | `create_employee` (line 82) | Sets `created_at` using naive `datetime.now()` and returns the raw datetime/string instead of integer epoch milliseconds. | Response contains an ISO string or datetime object instead of epoch milliseconds. | Stored UTC datetimes in Mongo and converted them to integer epoch milliseconds (`dt_to_epoch_ms`) at the API boundary. |
| 10 | `list_employees` (line 93) | Off-by-one pagination bug: `skip = page * page_size` skips the first page entirely. | Requesting `page=1, page_size=20` calculates `skip=20`, skipping records 1–20 and returning records 21–40. | Changed calculation to `skip = (page - 1) * page_size`. |
| 11 | `list_employees` (line 94) | `total` uses `count_documents({})`, returning the total company count rather than applying the department filter. | `GET /employees?department=Engineering` returned total company count instead of Engineering count. | Changed to `count_documents(q)` to count only filtered documents. |
| 12 | `list_employees` (line 95) | No sort order applied to the employee query. | Employees return in whatever natural order Mongo stored them, rather than sorted by `emp_code` ascending. | Added `.sort("emp_code", 1)` to the query. |
| 13 | `punch_in` (line 101) | Doesn't verify that the employee exists before reading `emp["shift_start"]`. | Punching in with a non-existent `emp_code` crashes with `TypeError: 'NoneType' object is not subscriptable` (500) instead of 404. | Checked `if not emp: raise HTTPException(404, "Employee not found")`. |
| 14 | `punch_in` (line 102) | Doesn't truncate punch instants to whole seconds per R1 before calculating dates or late minutes. | Sub-second millisecond offsets bleed into storage and cause precision mismatches in boundary calculations. | Truncated incoming timestamps to whole seconds (`microsecond=0`) right after parsing. |
| 15 | `punch_in` (line 103) | Derives the shift date using `ts.date().isoformat()` in local/UTC time, ignoring IST and night shift rollbacks. | A punch-in at 02:00 IST for a night shift gets tagged with today's date instead of the shift's starting date. | Parsed timestamps in IST and applied R1 overnight shift attribution logic. |
| 16 | `punch_in` (lines 104-105) | Check-then-insert race condition on attendance: queries `find_one` before `insert_one`. | Two concurrent punch-ins for the same employee and date both pass the check and create duplicate records. | Added a unique compound index on `(emp_code, date)` and handled `DuplicateKeyError` to return 409. |
| 17 | `punch_in` (lines 118-120) | Returns internal `id: str(res.inserted_id)` and raw BSON datetime objects. | API response includes an unwanted `id` field and non-integer timestamps, breaking the contract. | Formatted records with `format_attendance_record`: stripped `_id` and converted datetimes to integer epoch milliseconds. |
| 18 | `list_attendance` (line 129) | Endpoint parameter `status: Optional[str] = None` shadows FastAPI's imported `status` module. | Calling `status.HTTP_400_BAD_REQUEST` inside the endpoint crashes with an `AttributeError`. | Used explicit HTTP integer status codes (200, 422, etc.) to prevent variable name collision. |
| 19 | `list_attendance` (lines 136-141) | Doesn't check if `date_from > date_to`. | `GET /attendance?date_from=2026-07-10&date_to=2026-07-05` returns 200 with an empty list instead of 422. | Added validation raising 422 if `date_from` is after `date_to`. |
| 20 | `list_attendance` (lines 144-147) | Loads the entire matching dataset into Python memory (`list(...)`) and sorts it in memory. | With 100k records, memory usage spikes and queries take several seconds to return. | Used database-level pagination `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` backed by an index. |
| 21 | `list_attendance` (line 145) | Only sorts by `date` descending, omitting the required secondary sort on `emp_code`. | Records on the same date return in arbitrary order rather than ascending by `emp_code`. | Changed sort to compound `[("date", -1), ("emp_code", 1)]`. |
| 22 | Startup lifecycle (missing) | No indexes created on startup; only Mongo's default `_id` index was present. | Queries run full collection scans (`COLLSCAN`), and uniqueness cannot be guaranteed under concurrency. | Set up a FastAPI lifespan handler calling `create_indexes()` to idempotently build all indexes on startup. |

Also note anything you looked at and decided was **not** a defect, and why:

1. **Synchronous PyMongo in standard `def` routes**:
   I considered switching to Motor for async I/O, but FastAPI runs standard `def` route functions in an external threadpool (`anyio.to_thread`). This avoids blocking the event loop while keeping the database client code simple and predictable.
2. **`load_dotenv()` at module top level**:
   `python-dotenv` has `override=False` by default, so it won't overwrite environment variables that are already set in the shell or injected by a grading harness.
3. **Keeping `employees` and `attendance_logs` in separate collections**:
   Embedding attendance logs as an array inside each employee document would cause unbounded document growth and risk hitting Mongo's 16MB document limit. Keeping them normalized is the right approach for transactional log data.
